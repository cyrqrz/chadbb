## Subir o ambiente na outra máquina

```sh
git fetch origin && git checkout mvp-familiar
nvm use            # Node 22.12+, linha 22 do .nvmrc
npm ci
```

Não usar pnpm: o layout de symlinks quebra o binário nativo do
`embedded-postgres` com `libpq.so.5: cannot open shared object file`. Se algum
`pnpm-lock.yaml` ou `pnpm-workspace.yaml` reaparecer, apagar junto com
`node_modules` e refazer `npm ci`.

No WSL, confirmar que a sessão enxerga o grupo `docker` (`docker info`) e que o
Node do PATH é o do Linux, não o do Windows.

```sh
npm run db:start && npm run db:reset
npm run db:test && npm run test:api
npm run guest:serve &          # a Edge Function precisa estar no ar para o teste de navegador
npx playwright install --with-deps chromium
npm run test:browser:local
```

Para usar a aplicação: `cp .env.example .env.local` e preencher com a URL da API
e a **publishable key** de `npx supabase status`. Nunca a `service_role`.

## Pendências técnicas, em ordem

1. **Teto técnico na quantidade da reserva.** `reservations.quantity` só exige
   `> 0`. Fraldas são contidas pelo limite do tamanho, mas mimo não tem limite
   nenhum: cabe até 2.147.483.647 em um único item. Sugestão:
   `check (quantity between 1 and 1000)`, documentado como proteção técnica de
   entrada e não como cota de presentes.
2. **Edição de convite.** `organizer_invitations` tem create, revoke, rotate e
   list. O M3 exige impedir redução do limite abaixo do já confirmado e mudança
   de tipo incompatível — regra sem operação que a exercite. Decidir entre
   implementar a edição com checagem de versão ou registrar que capacidade e
   tipo são imutáveis e a correção é revogar e reemitir.
3. **Erros de domínio no RSVP.** `response` inválido cai na check constraint
   (23514) e `attending` ausente vira 23502; `'pending'` é aceito como resposta.
   O plano pede mensagem compreensível: falta `RSVP_INVALID_RESPONSE` e
   `ATTENDING_ABOVE_CAPACITY`.
4. **Retenção.** `private.guest_requests` cresce sem expurgo e guarda payload de
   RSVP; só `guest_rate` tem limpeza. A retenção de 90 dias do M6 precisa cobrir
   `guest_requests` e `guest_sessions`.
5. **Medir antes de assumir o p95 de 2 s.** `private.committed_quantity` é
   chamada por item em cada snapshot (27 itens) e todo `guest_action` devolve
   snapshot. Com 50 convidados e consulta periódica de 5 s, vale uma agregação
   única por evento antes do ensaio de carga.
6. **Limpeza.** `20260911020000` tem código morto: o `update ... set
   quantity_requested = null` é no-op e `treats_have_no_quota` já é implicado
   pela bicondicional de `20260911010000`. `prepare_family_list` fixa
   6/19/19/6 em migration e tem uma exceção sem `using errcode`.

## Antes de publicar no ambiente do evento

`GUEST_ALLOWED_ORIGINS` da Edge Function tem default de localhost e **precisa ser
configurada**, senão a origem de produção é bloqueada. Requisição sem cabeçalho
`Origin` passa pelo filtro: navegador sempre envia em POST cross-origin, então o
abuso via site de terceiro está barrado, mas um script direto não. A defesa real
são as cotas por rede, IP e credencial e o token de 64 hex — não tratar a
checagem de origem como controle de acesso.

## Decisões que faltam do solicitante

- **Data do chá.** `expires_at` do convite é `starts_at + 7 dias` e a publicação
  exige data futura. Sem ela não há como emitir convites reais nem fechar o
  ensaio do M5.
- **Limite por convite.** Não existe nenhum. Com 50 pacotes no total e cerca de
  50 convidados, os primeiros a responder podem levar a lista inteira. A regra
  "vários pacotes" foi confirmada; a consequência talvez não. Resolver antes de
  fechar o M4, porque mudar depois mexe em schema.
- **Quem presta suporte no dia** e o dia exato de entrega.
